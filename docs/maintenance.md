# Maintenance

Start with [AGENTS.md](../AGENTS.md). This guide covers routine repository work; [operations](operations.md) owns cloud release, review and recovery procedures. [Delivery evidence](delivery.md) records past verification and must not be read as a current health check.

## Choose the smallest useful check

| Change or task | Verification |
| --- | --- |
| Documentation, paths, artifact cleanup | `npm run check:docs`, inspect links and diff; no application deployment needed just to inspect the result |
| Worker rules or API | `npm run typecheck`, `npm run lint`, `npm test`; E2E if the browser/API contract changes |
| Schema or release scripts | Unit tests plus `npm run check:migrations`; follow operations before any remote action |
| Interface, styles, browser behavior | Typecheck, lint and `npm run test:e2e`; inspect relevant generated desktop/mobile screenshots |
| CI, test harness or cross-cutting change | `npm run verify` |
| Preparing an authorized PR | Full `npm run verify`, review diff/status, then exact-commit CI after push |

`npm run verify` is also the command used by Actions. E2E builds once, applies migrations to a fresh local `.wrangler/e2e-<timestamp>` directory and owns port 8791. It refuses to reuse another server. If that port is occupied, identify its owner; do not stop an unknown process. Never replace this local target with a production URL.

Use Node 24 and the lockfile (`npm ci`). Install Chromium once with `npx playwright install chromium` if it is missing. A missing dependency is not a reason to upgrade the lockfile. Migration checks require `origin/main`; refresh with `git fetch --no-tags origin main:refs/remotes/origin/main` before release preparation. All ordinary verification runs without cloud credentials.

## Generated files and repository size

| Path | Policy / regeneration |
| --- | --- |
| `src/`, `worker/`, `migrations/`, `tests/`, `scripts/`, configs and lockfile | Keep: application and reproducible tooling |
| `public/art/`, `docs/design/` | Keep: optimized runtime images, original artwork and provenance; `node scripts/assets.mjs` regenerates runtime images |
| `docs/evidence/` | Keep: selected, reviewed historical screenshots and receipts used by README/delivery |
| `artifacts/e2e/` | Ignored current test screenshots/traces; generated by `npm run test:e2e`; the next E2E run replaces this output |
| `artifacts/performance.json`, `artifacts/capacity.json` | Ignored current profiling results; review before manually promoting evidence |
| `dist/` | Reproducible build; `npm run build`; keep if a local static Worker is using it |
| `.wrangler/e2e-<timestamp>/`, `.wrangler/tmp/` | Local test/build residue; recycle only exact directories after their processes finish and useful failure evidence is retained |
| `.wrangler/state/` | Local development database/state; preserve unless a reset is explicitly requested |
| `node_modules/` | Local dependencies, intentionally retained for maintenance; `npm ci` can recreate them if separately selected for recycling |
| `.git/`, external backup keys/exports, credentials, shared browser caches | Preserve; never sweep them as project build residue |

Legacy `test-results/` and `playwright-report/` remain ignored for old runs. New browser output goes under `artifacts/e2e/`; CI uploads only this run's browser artifacts for seven days. Routine tests/profiling must not change tracked evidence.

For a cleanup, first record exact paths, purpose, sizes, tracked/ignored status and active process ownership. Verify resolved paths remain inside this checkout and contain no reparse points. Use the Windows Recycle Bin for approved candidates, keep a receipt outside the repository, and confirm the sources are absent. Do not empty the bin. Moving files to the same drive's Recycle Bin reduces checkout size, not necessarily disk use. Removing ignored files does not reduce Git clone size; do not rewrite Git history for routine tidying.

## Evidence discipline

`node scripts/performance.mjs <url>` measures a page without submitting bottles; its default target is local port 8787 and must already be running. `node scripts/capacity.mjs` uses synthetic in-memory local D1 only. Results go to `artifacts/`, not the published baseline. Keep all runs and record network/CPU conditions; browser viewport simulation is not physical-device verification.

To update accepted evidence, inspect the new output, select relevant files, copy them into `docs/evidence/`, and update the dated delivery record in the same change. Do not copy visitor messages, tokens, database exports or private keys into the public repository. `npm run check:docs` checks Markdown/image local target paths offline; it does not verify URL availability or heading anchors.

## Routine live maintenance

1. Read-only health: open the homepage and composer; check `/api/bootstrap` status, JSON/no-store behavior and secure cookie attributes without logging the cookie/token. Do not submit, open random visitor messages or report bottles just to prove the page loads.
2. For a release claim, match the actual remote main SHA to the required Actions check, the successful official Cloudflare build and its deployed Worker version. Check the live artifact and API, not just a green badge. Report each unavailable check separately.
3. When authorized for moderation, follow [operations](operations.md); list pending/flagged bottles privately, review them, and change only exact IDs. Starter editorial content is not a disposable test dataset.
4. Check backup recency and provider usage when doing operational review. Backups currently run with production releases, not on a daily timer; seven-day retention does not promise a fresh backup during a quiet week. Daily backups would be a separate authorized change.

No recurring monitor or new automation is implied by this guide. Remaining product validation includes real phones/soft keyboards, field performance and larger-pool hosted D1/CPU capacity. Historical mobile LCP narrowly missed its target; do not erase that result or claim it fixed without new measurements.

## Closeout record

Report the changed paths and purpose, commands actually run and outcomes, inspected evidence, any recycled paths/bytes, and remaining manual checks. Distinguish local verification from remote CI/deployment. If publication is authorized, preserve the protected-PR and official-build path; documentation-only changes pushed to the existing integration may still trigger a build.
